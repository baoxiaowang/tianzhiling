## 四、处置

### 4.1 新增封禁能力（发布 `0ac332c`）

系统原本**没有封禁机制**：`UserAccountStatus` / `UserLoginAccountStatus` 只有 `active` / `canceled`，而 `canceled` 是「用户注销」语义，会被注销流程扫描并触发**数据清理**（`account-cancellation.service.ts`），直接拿来封禁会销毁证据。因此新增独立状态：

- 两个枚举新增 `banned`；用户实体新增 `bannedAt` / `banReason` 审计字段；
- `ensureUserAccountActive` **优先**判定封禁：用户级或登录账号级命中即抛 `ACCOUNT_BANNED`（403）；
- 鉴权中间件对封禁状态拒绝既有 token，并把 `banned` 写入状态缓存（**不写注销标记**）；
- `findWeappAccountByOpenid` 不按状态过滤 → 同一微信 openId 登录时命中被封账号并**被拒绝，不会回落成新建账号**绕开封禁。

### 4.2 执行封禁（生产数据变更）

```
userId  6ac3e0dfe1501543673c2028
  accountStatus: active → banned
  bannedAt:      2026-10-09T05:15:41.061Z
  banReason:     腾讯云违规通知（色情内容）…滥用上传通道托管违规内容
user_account（openId oUF-y7Qjs9Xf37ocrk4pXCgwhnCM）
  status:        active → banned
Redis  auth:user-status:<userId> 已删除（否则最长 300 秒延迟生效）
```

### 4.3 可复用封禁步骤

1. 定位 userId 与 openId（`user` / `user_account`）；
2. `user.accountStatus = banned` + `bannedAt` + `banReason`；`user_account.status = banned`；
3. `DEL auth:user-status:<userId>` 立即生效；
4. 解封：状态改回 `active`、清空 `bannedAt`/`banReason`，同样删缓存；
5. 注意：**不要**用 `canceled` 代替封禁（会触发注销数据清理）。
