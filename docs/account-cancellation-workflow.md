# 账号注销工作流

## 产品入口

- 入口：`我的 -> 个人资料 -> 注销账号`。
- “退出登录”仍是高频可恢复操作；“注销账号”使用次级灰色入口，避免误触。
- 注销页先展示数据、声音、会员权益和必要业务凭证的处理方式，再允许用户确认。

## 操作流程

1. 页面请求 `GET /api/user/me/cancellation-check` 检查当前账号。
2. 有待支付、发放、退款订单，或声音剪辑/训练任务时，阻止注销并提供业务页面入口。
3. 用户勾选不可恢复提示，并输入固定确认文字“确认注销”。
4. 小程序重新调用 `Taro.login`，后端使用新的 `jsCode` 复核微信身份。
5. 页面请求 `POST /api/user/me/cancel`。后端先把账号标记为已注销并写入用户级 Redis 撤销标记，使所有设备上的旧令牌立即失效。
6. 后端删除或去标识化个人数据，注销登录账号，终止会员和未使用权益。
7. 首次清理部分失败时，写入失败阶段和待删除对象 key，并通过 `account-cancellation-cleanup` 队列指数退避重试 5 次。
8. 小程序清除本地登录态并回到首页。同一微信以后可以注册新账号，但旧账号的数据和权益不能恢复。

## 数据处理边界

| 数据 | 注销处理 |
| --- | --- |
| 用户昵称、头像、手机号、地区、偏好 | 删除或置空，用户记录保留为“已注销用户”状态桩 |
| 登录账号、微信 OpenID、密码 | 去标识化并解除 OpenID，状态改为 `canceled` |
| 用户创建的天之灵 | 删除天之灵、资料事实、长期记忆、关系信号和分享关系 |
| 共享天之灵 | 删除当前用户自己的共享关系、会话和私人记忆，不删除其他创建者的天之灵 |
| 聊天、媒体、聊天导入 | 删除会话、消息、反馈、导入批次、识别项及个人 COS 文件 |
| 朋友圈内容 | 删除本人动态、评论、点赞及包含本人快照的通知 |
| 声音数据 | 复用现有声音删除服务，删除原素材、切片、训练音频、预览、供应商声音模型并解除天之灵绑定 |
| 声音业务记录 | 保留会话事件、任务标识和删除审计，符合声音业务完整留痕要求，不再向注销用户提供服务 |
| 会员和权益 | 活跃会员改为 `canceled`，可用或已使用权益改为 `expired` |
| 订单、支付、退款、优惠账本 | 不删除；仅限履约、审计、退款与争议处理，前端不再可访问 |

## 兼容与安全

- 历史 `UserEntity.accountStatus` 和 `UserAccountEntity.status` 缺失时按 `active` 处理，兼容旧数据与旧小程序。
- 旧版本接口和响应字段不移除、不改名；注销只增加新路由与可选字段。
- 后端登录签发前会拒绝 `canceled` 用户；鉴权中间件还会检查永久用户级撤销标记。
- 微信账号已绑定时必须匹配原 OpenID。纯手机号账号要求有效当前令牌、当前登录账号归属正确，并完成一次新的微信登录验证。
- 日志只记录用户 ID、清理阶段和对象 key 哈希，不记录手机号、OpenID、素材内容或原始对象 key。

## 接口

### `GET /api/user/me/cancellation-check`

返回 `eligible`、`blockers`、`consequences` 和 `confirmationText`。阻断项目前包括：

- `ORDER_PROCESSING`
- `VOICE_PROCESSING`
- `IMPORT_PROCESSING`

### `POST /api/user/me/cancel`

请求体：

```json
{
  "jsCode": "fresh-wechat-login-code",
  "confirmation": "确认注销"
}
```

返回注销时间和清理状态。`cleanupStatus=processing` 表示账号已经不可登录，剩余数据由后台队列继续清理。

## 运维检查

- 监控 `account-cancellation-cleanup` 失败任务，人工处理超过 5 次仍失败的第三方声音模型或对象存储文件。
- 不允许通过恢复 `accountStatus` 的方式恢复账号；需要重新注册。
- 订单或退款仍在进行时不得绕过阻断。必要时先完成退款或关闭待支付订单。
