## 修订后的观测契约

采用轮次摘要＋`replyMemoryPackageDetails`有界数组，全部无新增索引，不含正文、标题或模型回答。诊断在生成上下文时形成，routing传递，保存时仅复制；不重新读配置、召回、计算热度或选择包。

| 字段 | 语义 |
|---|---|
| replyMemoryModuleConfiguredMode | 配置模式 off/shadow/active |
| replyMemoryModuleMode | 本轮有效模式 |
| replyMemoryScopeMatched | 范围命中；配置off时留空 |
| replyMemoryExecutionStatus | 主模块 not_run/succeeded/empty/failed；不是整个legacy检索状态 |
| replyMemoryShadowStatus | 影子召回 ok/empty/skipped/failed，未执行留空 |
| replyMemorySkipReason | module_off/scope_missed/service_unavailable/path_not_run/gate_suppressed/no_package_match/recall_failed/package_not_selected/context_not_injected |
| replyMemoryPackageInjected | 主路径包材料确实保留在组装后的初始模型请求；不等于模型采用或用户看到 |
| replyMemoryLegacyFallback | 目标召回引擎不可用而实际改用legacy；正常默认legacy为false |
| replyMemoryPackageDetails | 每项 source、engine、groupId、members、retained、heat、score、stage、reason；未知数值留空 |
| replyMemoryPackageDetailsTruncated | 因数量或字节预算省略明细；不改变包选择和正文 |

例：configuredMode=shadow / mode=off / scopeMatched=false / skipReason=scope_missed，表示配置了影子模式但当前用户不在名单。

明细 source=primary/shadow；stage=recalled/selected/injected。primary的retained表示最终上下文保留的成员数，shadow的retained表示影子召回的成员数，二者必须结合stage解读。热度取引擎已有计算值，score取选择器已有排序分，不在保存时重算。影子没有运行注入选择器，本轮不伪造“wouldInject”。

最多4项，每项BSON≤256字节，整份观测快照BSON≤1024字节，以实测序列化尺寸裁剪，实际可容纳数量可能少于4；优先保留实际注入包。采用256而非未经测量的200字节，以容纳完整语义字段；不承诺1KB覆盖原有消息字段或Mongo索引存储。全部气泡携带同一快照，统计按replyGroupId去重。

不能仅凭“mode=shadow且PackageInjected=true”判bug：shadow只约束影子分支；如果主召回另被配置为包引擎，主路径也可能注入。应检查来源为shadow的材料是否进入正文。本候选不会将shadow结果合入主结果。

## shadow前置核查结果

1. facade在shadow下同时执行主召回与影子召回；只将主结果交给context。影子异常被捕获，单测验证主提示不变。但Promise.all会等待影子分支，不能宣称零延迟影响。
2. shadow ingest会调用配置的主/影子引擎；事件引擎可写memory_event_group、开放项及回避反馈，shadow不是只读。
3. semanticIndex消费路径还会安排开放项抽取、调用inline抽取及模块ingest。inline抽取在条件满足时可发起额外模型调用，本轮未调用外部模型。
4. CHAT_SKIP_MEMORY_WRITE是窄开关；MILVUS_INDEX_ENABLED=true可放行semanticIndex入队。MEMORY_WRITE_DISABLED总闸在任务入口/消费有另外的限制。单测验证窄开关不等于阻止任务入队；不能据此断言生产写入一定发生或完全不发生。
5. 因此下一阶段需单独列清小名单、主/影子引擎、召回引擎、写入与抽取允许范围，再决定是否启用。本候选不顺手改这些行为。
