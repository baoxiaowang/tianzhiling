# T4：画像事实分类门控（路径 E 修复）

> 修复旧记忆乱入的路径 E：profile facts 独立入口无门控。
> 按事实类型分三类门控，不一刀切。

## 问题

生产诊断确认：画像事实（agent_profile_facts）不经检索/请柬/历史/摘要，直接进入上下文。案例："天气凉了"→ AI 提及"高铁站接人"（画像中有此事实）。用户本轮没提，事实不该注入。

## 方案

### 事实分三类

在 `apps/node/src/service/agents/agent-profile-fact.service.ts`（或对应文件）中，为画像事实增加分类字段或分类函数：

```ts
type ProfileFactClass = 'identity_relationship_style' | 'episodic_event_preference' | 'sensitive_taboo';
```

分类规则（按 fact key 或内容判断）：

```text
identity_relationship_style（always，不要求 cue）：
  用户称呼/亲属关系/角色身份/方言偏好/说话风格
  对应 key 前缀或内容含：称呼、关系、身份、方言、风格、preferred_name、address

episodic_event_preference（cue-gated，用户提到才注入）：
  事件/经历/偏好/近况/活动
  对应内容含：去过、做过、吃过、生病、住院、复查、工作、上学、搬家、旅行

sensitive_taboo（user_initiated_only，用户主动打开才注入）：
  禁忌/敏感话题/与逝者的冲突
  对应内容含：禁忌、不想提、回避、吵架、矛盾
```

### 门控实施

在 `agent.context.ts` 的画像事实注入处（搜索 `profileFacts` 或 `buildAgentProfileEvidence`）：

```text
identity_relationship_style → 直接注入（现状不变）
episodic_event_preference → 检查当前用户输入（currentQuery）：
  包含相关人物名/事件词 → 注入
  不包含 → 跳过该条事实
sensitive_taboo → 只有当前用户输入明确提到相关话题 → 注入
  否则跳过
```

相关人物名/事件词的匹配：用画像事实自身的内容词与用户输入做简单交集（不是新关键词表）。

## 验收

1. 单测：
   - identity 类事实 → 始终注入
   - episodic 类事实 + 用户提到相关词 → 注入
   - episodic 类事实 + 用户未提 → 不注入
   - sensitive 类事实 + 用户未主动打开 → 不注入
2. 生产场景模拟："天气凉了"（用户未提接人）→ 接人事实不注入
3. 人格不退化："我回来了"（identity 类正常注入，模型知道怎么称呼）

## 边界

- 只改注入门控，不改事实的存储/更新/归档
- 分类函数是纯函数，可单测
- 不新增持久状态
- 分类不确定的默认 identity（宁多勿少，防人格断裂）
