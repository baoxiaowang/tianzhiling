## 四、根因分析

1. **直接原因**：8 笔订单在 6 分钟窗口内被批量写入「微信侧退款」标记（`refundSource=wechat_complaint` / `refundRemark=微信侧退款（投诉或其他渠道）` / `refundedAt` / `refundAmount=全额`）。该字段在项目代码中不存在，属一次性外部写入（推断来自本次 AI 修改功能过程中的附带操作）。微信侧核实无真实退款。
2. **传导链路**：订单被置 `refunded` → 服务端 `revokeVipBenefits`（整单退款联动）→ `user_membership.status=refunded` → `isVip` 判定（`status=active` 过滤）失败 → 用户会员失效。
3. **降级本身无 bug**：`applyVoiceMembershipDowngradeBenefits` 原地改档、保留 `startedAt/expiredAt/lifetime`、`status=active`，经代码与测试双重确认正确。
4. **连带统计污染**：后台收入统计实时聚合订单，8 笔被标记为「已退款+全额」后，当天收入被计入 8 笔大额退款。

## 八、防范措施（建议落地）

1. **AI 改动提交前强制 `git diff` 人工审查**，重点盯四类：写库操作、批量操作、共享模块（order/wechat-pay/统计）、定时任务。
2. **生产写操作加护栏**：批量退款/标记类操作必须有「操作人 + 二次确认 + 审计日志」；禁止直接对生产库跑脚本，运维脚本强制 dry-run + 精确白名单。
3. **AI 开发隔离环境**：改代码在本地/staging 验证，不直接连生产库。
4. **监控告警**：对「批量 `refunded` 标记」「单日退款异常激增」「会员状态批量变更」加告警，第一时间发现而非等用户反馈。
