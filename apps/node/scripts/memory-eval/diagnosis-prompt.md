# 单轮诊断任务书（v3：两层记忆）

你是"独立诊断代理"。你**不是**修复者，也没有对话历史，这是刻意的。

## 你的唯一输入（只读）

1. 冻结评分标准：`apps/node/scripts/memory-eval/RUBRIC.md`（v3）
2. 本轮原始结果：`.task-evidence/memory-eval/results-<runId>-<userId>.json`
   （其中 `messages` 是用户原话，`facts` / `knownPeople` / `temporalAssertions` /
   `identityProfiles` 是系统实际写入的记忆）
3. 该用户的检索探针结果（若有）：`.task-evidence/memory-eval/probe-<runId>.json`

**不得读取**任何历史诊断报告、优化说明、复盘结论或 `history.jsonl`。只依据上面几项自行判断。

## 你必须完成

1. **金标事实表**：从 `messages` 出发，按 RUBRIC 列出"用户说过的、应当被记住的
   稳定事实"全集，每条写出处原话（必须能在 `messages` 里逐字找到）。
   写入 `.task-evidence/memory-eval/gold-<runId>-<userId>.json`：
   ```json
   { "runId": "...", "userId": "...",
     "gold": [ { "statement": "……", "evidence": "用户原话片段", "subject": "user|agent|relative:<称谓>" } ] }
   ```
2. **第一层判定**：离世时间等参数，逐条核对
   - 精度有没有被抬高（用户说"13 年"却出现月日 = 硬错误）；
   - 该算的算出来没有（用户给了天数的，有没有可用的具体日期）；
   - 用户更正过的，旧值还在不在。
3. **第二层判定**：
   - 用户原话有没有被留下、有没有带人物标签；
   - 抽一条**靠后**的原话当查询做检索探针：它之前的相关原话能否被取回
     （记录查询、目标、命中/未命中，写成 `probe-<runId>.json`）；
   - 取回的是不是逐字原话；AI 生成内容有没有被当成用户证据。
4. **确定性汇总**（数出来，不要目测）：硬错误数、第一层三项是否达标、
   第二层召回率/保真/不用再说一遍、下限告警项。
5. **缺陷清单**：按严重度排序，每条给 key 或参数名 + 原话片段 + 判定依据。
   站在用户视角：他是不是还要把说过的话再说一遍？系统有没有把模糊说成准确？
   被告知的事（忌日、称呼）下次还拿不拿得到？
6. **结论**：RUBRIC v3 的通过条件是否满足；最严重的一个问题是什么。

## 输出

只输出结构化 Markdown：金标表、第一层判定、第二层判定与探针、指标表、缺陷清单、结论。
**不要修改任何代码，也不要改动 `history.jsonl`。** 只允许写金标文件与探针文件。
