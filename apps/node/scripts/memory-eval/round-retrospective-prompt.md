# 一轮（15 个用户）小复盘任务书（固定 v1）

你是"独立复盘代理"。你**不是**任何一批的诊断者，也**不是**修复者。你没有对话历史，这是刻意的。

## 背景

一轮 = 5 批 × 3 个用户 = **15 个真实用户**，用同一份固定配置抽取记忆。每批都由独立诊断代理评测过。

## 你的唯一输入（只读）

1. 冻结评分标准：`apps/node/scripts/memory-eval/RUBRIC.md`
2. 固定闭环方法：`apps/node/scripts/memory-eval/LOOP.md`
3. 本轮 15 个用户的评测结论与指标：`<由调用方给出具体路径>`
4. 本轮 15 个用户的原始结果目录：`.task-evidence/memory-eval/results-memory_rebuild_<轮次>_*.json`
5. 各用户的冻结金标准：`.task-evidence/memory-eval/gold-*.json`

**不得读取**任何修复说明、代码 diff、优化者自述、其他轮次的结论。

## 你必须完成

1. **指标汇总表**：15 个用户逐一列出 稳定事实召回率、情绪当事实率、称谓错误率、重复率，并给出：
   - 每项指标的 最小值 / 最大值 / 中位数 / 极差
   - 四项门槛各自在多少个用户上达标（例如"召回：1/15 达标"）
2. **高频缺陷排序**：按出现用户数排序，每类给出：
   - 出现在哪些用户、哪些条目（key）
   - 用户原话片段作为证据
   - 根因层次（提示词 / 解析校验 / 去重 / 主体绑定 / 覆盖策略 / 结构化记录）
3. **共性与个案**：跨 ≥2 个用户重复出现的算共性；只出现在单个用户的算个案。个案只登记为观察项，**不要**据此改规则。
4. **建议动作**：只对共性问题提，且必须能追溯到上面列出的证据。
5. **一眼就能看出来的问题**：单独列一节，指出最明显、最不需要争论的问题（例如"同一人被拆成多个身份""某类内容整段丢失""某个护栏完全没生效"），并给出你判断它"一眼可见"的依据。
6. 明确回答：这一轮有没有任何用户四项全达标？最该优先解决的一个问题是什么？

## 输出

只输出结构化 Markdown：指标汇总表、高频缺陷表、共性 vs 个案、一眼可见的问题、建议、结论。
**不要修改任何文件。**
