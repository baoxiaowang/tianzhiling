# 记忆质量评分标准（v3：两层记忆）

> v1、v2 已冻结留存：`RUBRIC-v1-frozen.md`、`RUBRIC-v2-frozen.md`。
> v3 的改动来自产品口径的重定：记忆分两层——**第一层是少量必须准的结构化参数，
> 第二层是用户原话的检索**。评测因此不再以"系统把这一家人理解得多全"为主判据。

## 零、判定前必须先做的一件事

评测任何用户之前，先只读 `messages` 产出并冻结一张表：

- **金标事实表**：用户说过的、应当被记住的稳定事实，每条标注出处原话与主体
  （用户本人／这位亲人／其他家人）。

（v2 要求同时冻结"金标人物表"，v3 不再强制：人物不再是主判据——系统只做出现
记录与检索标签，谁是谁由模型判断。）

没有金标事实表的轮次**视为无效轮次**，不得用于趋势或对照结论。

## 一、硬错误（必须为 0，任一不为 0 即整轮不通过）

| 硬错误 | 定义 |
| --- | --- |
| **精度抬高** | 用户只给模糊时长/时点，系统写出更精确的日期（说"13 年"却写月日） |
| **编造** | 写出用户原话里不存在的人、关系、日期或状态 |
| **原话被当成事实以外的来源** | 把 AI 自己生成的话当成用户说过的证据 |
| **该记的整类丢失** | 金标里的某一整类（离世与时间、话题与事件等）一条都没留下 |

## 二、第一层判据（结构化参数）

| 判据 | 怎么判定 | 门槛 |
| --- | --- | --- |
| 精度忠实 | 参数精度 ≤ 用户给出的精度；同人多次说法取了最细且不冲突的那次 | 抬高 = 0 |
| 算得出来、能调用 | 用户给了可算参数时，系统确实算出了可用的值（如"走了多久"的具体日期） | 该算的都算出来 |
| 更正生效 | 用户更正后，旧值不再被引用 | 全部生效 |

## 三、第二层判据（原文检索）

| 判据 | 怎么判定 | 门槛 |
| --- | --- | --- |
| 召回（宁多勿漏） | 给一句新的用户原话，构建检索请求，看相关的旧原话是否被取回 | 相关旧话被取回 ≥ 0.80 |
| 保真 | 取回的内容是**逐字原话**；AI 生成内容被标为生成、未当作用户证据 | 全部保真 |
| 不用再说一遍 | 金标事实中，用户已经说过但检索取不回的比例 | ≤ 0.20 |

> 检索探针怎么做：从该用户的 `messages` 里取一条**后面的**原话当查询，把它之前的
> 相关原话当目标，看检索结果里有没有。探针必须可复现（记录查询、目标、命中结果）。

## 四、下限告警（不作为通过条件）

| 指标 | 定义 | 告警线 |
| --- | --- | --- |
| 原话留存率 | 被索引的用户原话条数 ÷ 用户原话条数 | <0.95 告警 |
| 人物标签覆盖率 | 带人物标签的原话条数 ÷ 提到家人的原话条数 | <0.80 告警 |
| 重复率 | 近义重复条数 ÷ 总条数 | >0.15 告警 |
| 情绪/状态入库 | 情绪、当下状态、带场景的哀伤表达被写入的条数 | >0 告警 |

## 五、通读验收

把该用户的记忆交给一个**没读过原文**的新代理，让它回答三个问题：
这家有谁？最近发生了什么？这个人最在意什么？

- 3 分：三问都能答对且不编造
- 0 分：答不出，或答错亲属关系
- 门槛：≥2 分

## 六、通过条件（v3）

一轮通过 = 硬错误全为 0 **且** 第一层判据全部达标 **且** 第二层三个判据全部达标
**且** 通读验收 ≥2 分。下限告警只作提示。

## 七、独立性

1. 诊断、复评、复盘由**不同代理**完成。
2. 金标事实表按用户冻结；复评若认为有误只写 `gold-proposal-*`，并同时用冻结版给出结果。
3. 指标由脚本确定性汇总；代理只做逐条判定与金标、以及可复现的检索探针。
4. 每批必须留下 `gold-<runId>-<userId>.json`、检索探针结果与 `batch-ledger.jsonl`
   记录，缺一即该批作废。
5. 跨用户、跨批次的数值差异**不得**作为程序变好/变坏的证据；只有同用户 + 同冻结
   金标的前后对照才算。
