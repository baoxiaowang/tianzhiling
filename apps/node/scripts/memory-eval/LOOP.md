# 记忆质量迭代闭环（固定方法 v4）

## 目标（一句话）

让记忆系统越来越像**这个人的档案**——一个人经历过什么、家里有谁、身体怎样、在意什么。
指标是探照灯，不是目标。

**只改代码，不发布；只写本地镜像库，不写生产。**

## 完整流程：以「批」为单位

一批 = 3 个聊天量相近的真实用户（并行）。**改代码只发生在批次之间。**

1. **开工冻结**：确认工作区已提交，把 commit 记进本批清单。
   批次运行期间**不得修改任何代码**——否则同批用户用的是不同版本，数据不可比。
2. **只读拉取**：从生产只读导出这 3 个用户到各自独立镜像库（`tzl_mirror_s*`）。
3. **本地回放**：用固定配置（批量 5 条）+ 真实模型重放，产出结果文件。
4. **独立诊断**：由 **3 个全新代理**分别负责一个用户，各自先建金标准再逐条判定。
   诊断代理**不得**读代码、历史结论、其他用户结果。
5. **批次末统一优化**：把本批诊断出的问题**汇总成一次改动**（可含多项），补单元测试，提交。
   —— 这是本批唯一允许改代码的时间点。
6. **记录**：批次、用户、commit、指标、缺陷、观察项写入 `.task-evidence/memory-eval/history.jsonl`。
7. **进入下一批**。

## 节奏

- **一轮 = 5 批 = 15 个真实用户**。
- **每轮末**：由独立复盘代理做**小复盘**（趋势 + 高频缺陷 + 共性与个案）。
- **每 2 轮**：挑一个此前跑过的批次（3 个用户）重跑，用其**冻结金标准**做同用户对照。
  **只有这份对照**可以说明程序是否进步。
- 相邻轮之间**不**重复对照同一批用户。

## 证据口径

- 每个用户的聊天内容差异极大：**跨用户、跨批次的数值差异不得**当作程序变好/变坏的证据。
- 新用户的首轮数字只是该用户的基线，用于发现缺陷，不用于排名。
- 只有「同一批用户 + 同一份冻结金标准」的前后对照（每 2 轮一次）才算进步证据。

## 反自证：不许把任务做成"给评估方法打分"

任何评估方法都有局限。以下为硬约束：

1. **指标只是探照灯**。门槛的作用是**指出哪里没做好**，**不允许**把"把某个比率压到门槛以下"当作改动理由。
2. 每条改动必须能回答：**用户的档案因此更像这个人了吗？** 答不出来就不改。
3. 每条改动必须自查副作用：**会不会让记住的内容变少、变假、或变得不可用？**
   若指标变好但内容变差，**以内容为准**，并把它记进观察项。
4. **禁止**仅为提升某个比率而扩大黑名单/白名单式的补丁；优先做结构性修复（谁能成主体、什么算家属、输出在哪一层被截断）。
5. **观察项台账**：指标覆盖不到的问题（例如"记忆读起来像哀伤日志，而不是人物志"）写入
   `.task-evidence/memory-eval/observations.jsonl`，复盘时一并看，不因"指标没这项"而丢弃。
6. **评估方法本身每轮受审**：每轮复盘必须回答——
   - 这一轮的指标还在衡量我们真正在意的东西吗？
   - 有没有出现"指标好、内容差"的迹象？
   - 本轮的改动里，有哪几条其实是为了刷指标？
7. **人工抽读**：每轮复盘时抽 3 个用户，把记忆当"人物档案"通读一遍，判断像不像一个人。
   若与指标结论冲突，以抽读为准，并把冲突记入观察项。
8. 冻结的评分标准不因"不达标"而修改；确需变更必须新建 version 并说明理由。

## 独立性与可审计

1. 诊断、复评、复盘必须由**不同代理**完成。
2. 评测集（`manifest.json`）与评分标准（`RUBRIC.md`）冻结。
3. 指标由脚本确定性汇总；代理只做逐条判定与金标。
4. 结果与复盘只追加、带时间戳，不覆盖；结果文件名必须含 `<runId>`。
5. **金标准按用户冻结**：同一用户的第一个 `gold-<userId>.json` 即为冻结版，后续轮次必须原样使用。
   复评若认为金标有误，只写 `gold-proposal-*` 提议，并**同时用冻结版给出可对比召回**。
6. 每个批次必须记录所用 **commit**；工作区不干净时批次标记为 `dirty=true`，该批数据视为可疑。
7. 批量大小等抽取配置在一轮内固定，不做横向对比。

## 运行方式

```bash
# 一整轮（5 批 × 3 用户 = 15 个用户，会先编译一次并冻结 commit）
bash apps/node/scripts/memory-eval/run-round.sh <roundName> <15 个 userId>

# 单批（3 个用户并行）
bash apps/node/scripts/memory-eval/run-parallel-users.sh <batchName> <userId1> <userId2> <userId3>
```
