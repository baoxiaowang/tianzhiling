# 记忆质量迭代闭环（固定方法 v1）

## 目标

用真实用户的真实聊天 + 真实模型，持续发现"记忆存得不对"的问题并修复。
**只改代码，不发布；只写本地镜像库，不写生产。**

## 每轮（一个真实用户）

1. **只读拉取**：从生产只读导出该用户的数据到本地镜像库 `tzl_mirror`。
2. **本地回放**：用当前代码 + 真实模型，在本地镜像上重放该用户的消息。
3. **独立诊断**：由**全新代理**仅依据 `RUBRIC.md` 与该轮原始结果，逐条判定"应保留 / 应降级 / 应丢弃"，给出指标与缺陷清单。诊断代理**不得**参考任何历史结论或优化者说明。
4. **优化**：针对缺陷改代码，并补单元测试。
5. **记录**：把本轮指标与缺陷追加到 `.task-evidence/memory-eval/history.jsonl`。
6. **进入下一个用户**。

## 每 5 轮：复盘

- 汇总最近 5 轮的指标趋势与高频缺陷。
- 由**独立复盘代理**（非诊断者、非修复者）判断：是共性问题还是个案。
- 只做两类动作：修正提示词/规则（普适问题），或登记为观察项（个案）。
- **不改冻结的评分标准**；如需变更，新建 version。
- 复盘的结论也必须能追溯到原始结果，禁止只给结论不给证据。

## 独立性要求

1. 诊断与复评必须由不同代理完成。
2. 评测集（manifest.json）与评分标准（RUBRIC.md）冻结。
3. 指标由脚本确定性汇总；代理只做逐条判定与金标。
4. 每轮结果与复盘只追加、带时间戳，不覆盖；结果文件名必须含 `<runId>`，禁止同名覆盖。
5. 若某轮指标相对上一轮恶化，先回到优化步骤，不进入下一个用户（棘轮）。
6. **金标准必须留清单**：诊断代理除指标外，必须写出 `gold-<runId>-<userId>.json`，逐条列出"按 RUBRIC 应保留的事实"及其出处原文片段；`history.jsonl` 里记 `gold_total` 指向该清单。缺清单的轮次，其召回率视为不可复核（无效轮）。
   - 历史遗留：前 6 轮只存了比率，未存清单，已在 `history.jsonl` 中标记 `gold_denominator_missing: true`，不回填猜测值。
7. **金标准按用户冻结**：同一用户的第一个 `gold-<userId>.json` 一经产出即为该用户的**冻结金标准**。后续轮次（含复评）**必须原样使用**它计算召回，不得增删改条目。
   - 复评代理若认为金标准有误，只**提议**修订，写进单独的 `gold-proposal-<runId>-<userId>.json`，并**同时用冻结版给出可对比的召回**。
   - 跨轮对比只承认"同一冻结金标准"下的数字；用不同金标准算出的召回不得并列比较（round6 → round6b 就因此产生过不可比数字）。
8. **同配置重复 3 轮**：真实模型的抽取本身有随机性。同一份代码必须对同一用户跑 **3 轮**，取**中位数**作为该配置的成绩，并记下极差。
   - 只有中位数的差异才作为"改善/恶化"的依据；单轮差异不得当作结论（round6b 与 round6c 代码不同、命中集合差别很大，召回却同为 12/24，说明单轮不可靠）。
   - 棘轮（第 5 条）同样基于中位数判定。

## 运行方式

```bash
bash apps/node/scripts/memory-eval/run-user-round.sh <userId> memory_rebuild_<name>
```
