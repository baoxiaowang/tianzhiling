# 记忆质量迭代闭环（固定方法 v5）

## 目标（一句话）

让记忆系统持续提升**录入能力**：一个人经历过什么、家里有谁、身体怎样、在意什么，
都被高质量、稳定地记下来——**记住、并且记好**。

指标是探照灯，不是目标。

**只改代码，不发布；只写本地镜像库，不写生产。**

## 评价立场（v5 新增，最重要）

评测**不得**只以程序自身的输出与标准为依据。任何一轮评估必须同时站在三个外部视角：

1. **用户时间**：用户为此说了几次、还要再说几次？
   同一件事被反复追问、或用户明明说过却没记住，都是录入能力的失败。
2. **产品体验**：这些记忆拿去做对话，会让人物"更懂这个人"吗？
   读起来像人物档案，还是像情绪日志 / 关键词碎片？
3. **工程视角**：这条记忆可检索、可更新、可纠正吗？
   同一个人会不会有多个身份？时间是精确的还是模糊的、有没有被伪造成精确？

四项比率（记全 / 情绪当事实 / 称谓错 / 重复）只是**下限探照灯**。
判一条记忆好坏，先问上面三个问题，再比率率。

**禁止**把"达标"当作完成；**禁止**只拿程序自己的输出去证明程序变好。

## 记忆质量维度（v5 扩展）

除四项比率，逐条记忆还要按下列维度看（诊断与复盘都要求覆盖）：

| 维度 | 要求 |
| --- | --- |
| 人物身份 | 一个人**只有一个身份**；称呼可变，身份不变 |
| 姓名与称呼 | 姓名要能**确认与修改**；同一人的多种叫法是他的**别名**，不是新的人 |
| 亲属关系 | 称谓必须来自用户原话，且相对**用户本人**（"爷爷的姐姐"不是用户的核心亲属） |
| 时间·去世/生日 | 能算出准确日期就给**准确日期**；算不出就如实记**宽泛时间**（如"约三年""2018年左右"），**绝不伪造精确度** |
| 时间·时长 | 用户说"226 天""23 年"这类时长要落库，并按参考时间换算得出可回溯的日期 |
| 可纠正性 | 用户后来说的更正要能覆盖旧值，而不是并存两条 |

## 完整流程：以「批」为单位

一批 = 3 个聊天量相近的真实用户（并行）。**改代码只发生在批次之间。**

1. **开工冻结**：确认工作区已提交、所选用户**近期活跃**（否则回放窗口取不到数据，
   会整段跑出 0 条记忆）；把 commit 记进本批清单。
2. **只读拉取** → 3. **本地回放**（固定配置、真实模型）。
4. **独立诊断**：3 个全新代理各负责一个用户，**先建金标准再逐条判定**；
   按上面的四视角 + 六维度出结论，不只看比率。
5. **批次末统一优化**：只修**一眼就能看出来**的问题（同一人多个身份、
   整类内容丢失、凭空捏造、同一 key 装两条事实…），合并成一次改动并补测试。
6. **记录**：批次、用户、commit、指标、缺陷、修改写入台账。
7. 进入下一批。

## 节奏与各层职责（v5 明确）

| 层级 | 职责 |
| --- | --- |
| **每批** | 只修"一眼就能看出来"的问题；改代码只在批次之间 |
| **每轮（5 批 = 15 用户）** | 轮末由独立复盘代理出**该轮的整体解决方案**——共性问题、根因分层、下一轮的优化主题，而不是逐条打补丁 |
| **每 2 轮** | **高层对照分析**：可以调整优化维度、也可以调整整个方案**包括评测体系本身**。问三个问题：<br>① 现在的指标还在衡量我们在意的东西吗？<br>② 有没有"指标好、内容差"的迹象？<br>③ 这一阶段的优化维度该换了吗？ |

- **只有"同一批用户 + 同一份冻结金标准"的前后对照**才算进步证据；
  跨用户、跨批次的数值差异一律不作为证据。
- 高层对照必须**先读记忆原文**（抽 3 个用户当人物档案通读），再看数字；
  冲突时以通读为准。

## 独立性与可审计

1. 诊断、复评、复盘必须由**不同代理**完成。
2. 评测集（`manifest.json`）与评分标准（`RUBRIC.md`）冻结；确需变更新建 version 并说明理由。
3. 结果与复盘只追加、带时间戳；结果文件名含 `<runId>`。
4. **金标准按用户冻结**；复评若认为金标有误只写 `gold-proposal-*`，并同时用冻结版给出可对比召回。
5. 每批记录所用 **commit** 与 dirty 标记（只检查影响记忆抽取的路径）。
6. 指标覆盖不到的问题写入 `.task-evidence/memory-eval/observations.jsonl`，复盘一并看。

## 运行方式

```bash
# 一整轮（5 批 × 3 用户 = 15 个用户，先编译一次并冻结 commit）
bash apps/node/scripts/memory-eval/run-round.sh <roundName> <15 个 userId>

# 单批（3 个用户并行）
bash apps/node/scripts/memory-eval/run-parallel-users.sh <batchName> <userId1> <userId2> <userId3>
```
